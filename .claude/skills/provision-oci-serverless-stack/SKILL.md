# provision-oci-serverless-stack

Routes to `@oci-serverless-stack` — the Full-Stack Serverless Deployer that orchestrates end-to-end
creation of OCI Functions + Terraform infrastructure + API Gateway routes in a single coordinated workflow.

## What the agent does

The agent is forked and has no sub-agent fan-out; the flow is user-mediated.

- Reads structured work-order records from `docs/handoff/<capability>/` (generated by `@oci-serverless-architect`) and validates the three streams.
- Ends with: "Hand off: run `/develop-java-function` (`@oci-functions-java`) and `/provision-oci-infra` (`@oci-terraform`) for streams A and B, then `/provision-oci-serverless-stack <slug> --integrate` for stream C and the cross-domain check."

## `--integrate` mode

`/provision-oci-serverless-stack <slug> --integrate` reads `result-java.md` and `result-terraform-infra.md` (both must report `outcome: success`, otherwise it stops with `needs-input`), then does stream C itself (Function resource, API Gateway route; writes `result-terraform-integration.md`) and runs the cross-domain checks: `mvn compile`, `terraform fmt -check`, `terraform validate`, `scripts/preflight.sh`, and config-key / IAM / route consistency. It ends with the hand-off to `/deploy-oci-function` (`@oci-deployer`).

## Stream model

```
Stream A (Java)                    Stream B (Terraform)
─────────────────                  ─────────────────────
/develop-java-function             /provision-oci-infra
(@oci-functions-java):             (@oci-terraform):
 • Handler class                    • Networking (VCN, subnet)
 • Model classes                    • IAM (dynamic groups, policies)
 • pom.xml dependencies
 • func.yaml config
         │                                   │
         └──── user runs both; result-*.md ──┘
                         │
              /provision-oci-serverless-stack <slug> --integrate
              (@oci-serverless-stack, stream C):
               • Function resource (needs func.yaml)
               • API Gateway route (needs function OCID)
```

## Pre-requisites

The handoff directory `docs/handoff/<capability>/` must contain:
- `stream-a-java.md` — Java function work-order
- `stream-b-terraform-infra.md` — independent Terraform work-order
- `stream-c-terraform-integration.md` — dependent Terraform work-order

These are produced by `/design-oci-architecture` (`@oci-serverless-architect`).

## Incremental addition mode

Use this agent with the argument of an existing capability when adding a function to an existing Application (`Stream D` workflow — additive only, no destroy operations).
