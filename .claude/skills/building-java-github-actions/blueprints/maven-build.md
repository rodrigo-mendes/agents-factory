## Wrapper pin

Hosted runners ship Maven 3.9.x, so a 3.10-only feature needs the wrapper (source: https://github.com/actions/setup-java/blob/v6.1.0/docs/advanced-usage.md).

```bash
# Run once locally, then commit mvnw, mvnw.cmd and .mvn/wrapper/maven-wrapper.properties
mvn wrapper:wrapper -Dmaven=3.10.0
```

```properties
# .mvn/wrapper/maven-wrapper.properties: add the checksum "to avoid supply-chain-attacks"
distributionSha256Sum=<sha256-of-apache-maven-3.10.0-bin.zip>
```

The checksum value was not resolved on a page; take it from the Maven download page and never copy a value from memory (unverified). Source: https://maven.apache.org/tools/wrapper/.

## Maven 3.10 behaviour changes

Source for the whole section: https://maven.apache.org/docs/3.10.0/release-notes.html.

| Change in 3.10.0 | Effect | Action |
|---|---|---|
| Stricter POM validation | many 3.9 warnings (duplicate dependencies or plugins) now fail the build | fix the POM; `-Dmaven.resolver.validation=off` is a temporary escape only |
| Classpath order breadth-first | classpath order differs from 3.9 | old behaviour via `-Daether.system.dependencyVisitor=preOrder` |
| Super POM | `release-profile` and plugin management removed; UTF-8 encodings and a default `project.build.outputTimestamp` set | declare plugin versions yourself |
| Reproducible Builds active by default | same inputs give the same archive | promote the same file, never rebuild |
| Credentials scoped to origins | a server id credential is sent only to origins Maven can associate with it | review `settings.xml` generated by setup-java |
| Toolchains | a misconfigured plugin-requested toolchain fails the build | fix `toolchains.xml` |

setup-java v6.1.0 `mvn-server-repository-origins` only works with Maven 3.10 and later (source: https://github.com/actions/setup-java/blob/v6.1.0/docs/advanced-usage.md).

Upgrade path: `mvn wrapper:wrapper -Dmaven=3.10.0`, commit, run `./mvnw -B -ntp verify`.

## Surefire and Failsafe

`verify` runs Failsafe integration tests ("invoke Maven with a phase of `verify` or later", https://maven.apache.org/surefire/maven-failsafe-plugin/usage.html). Reports land in `${project.build.directory}/surefire-reports` and `${project.build.directory}/failsafe-reports` (pages: https://maven.apache.org/surefire/maven-surefire-plugin/test-mojo.html, https://maven.apache.org/surefire/maven-failsafe-plugin/integration-test-mojo.html).

```xml
<plugin>
  <artifactId>maven-surefire-plugin</artifactId>
  <version><!-- current version from the Surefire plugin page --></version>
</plugin>
<plugin>
  <artifactId>maven-failsafe-plugin</artifactId>
  <version><!-- same Surefire line, from the Failsafe plugin page --></version>
  <executions>
    <execution>
      <goals><goal>integration-test</goal><goal>verify</goal></goals>
    </execution>
  </executions>
</plugin>
```

The pages showed 3.6.1 on 2026-10-30 in the page header, not on a release page (medium confidence); the version is not a family fact, so keep the placeholder and read the current version from https://maven.apache.org/surefire/maven-surefire-plugin/. Never set `testFailureIgnore` ("Its use is NOT RECOMMENDED").

## JaCoCo

Source: https://www.jacoco.org/jacoco/trunk/doc/maven.html, an unversioned trunk page, so the details below are (medium confidence).

```xml
<plugin>
  <groupId>org.jacoco</groupId>
  <artifactId>jacoco-maven-plugin</artifactId>
  <version><!-- current version from https://www.jacoco.org/jacoco/trunk/doc/changes.html --></version>
  <executions>
    <execution><goals><goal>prepare-agent</goal></goals></execution>
    <execution><id>report</id><phase>verify</phase><goals><goal>report</goal></goals></execution>
  </executions>
</plugin>
```

- The agent needs forked test execution: a `forkCount` of 0 prevents the javaagent.
- With a custom Surefire `argLine`, use late replacement `@{argLine}`.
- The HTML report is written to `target/site/jacoco/index.html`; the reusable workflow uploads `target/site/jacoco/`.
- The page showed 0.8.16 (2026/10/24), supporting up to Java 27; 0.8.14 added Java 25. Keep the placeholder; the version is not a family fact.
- Failsafe coverage needs the integration agent goal; not verified here.

## Lambda JAR with Shade

`maven-shade-plugin` bound to `package` with `createDependencyReducedPom=false` yields one JAR in `target/`. The AWS page shows an old Shade version, so the current one is a placeholder (unverified):

```xml
<plugin>
  <artifactId>maven-shade-plugin</artifactId>
  <version><!-- current version from the maven-shade-plugin page --></version>
  <executions>
    <execution><phase>package</phase><goals><goal>shade</goal></goals>
      <configuration><createDependencyReducedPom>false</createDependencyReducedPom></configuration>
    </execution>
  </executions>
</plugin>
```

Layout choices and limits: [Lambda zip and image hand-off](./lambda-and-image-handoff.md).
