# Guide: Creating Agents

How to create a complete agent project in Claude Code.

> **Note**: The `agent-bootstrap` artifact was cancelled and never implemented. To create a
> new agent project, start with `/skill-creator` to create the individual skills and organize them
> under `.claude/`. The project structure follows the Agent Router Pattern conventions described below.

---

## When to Use

- Starting a new automation domain
- Structuring an agent that needs skills, rules, and commands
- Ensuring adherence to the Agent Router Pattern from the start

## Step by Step

### 1. Research the domain technologies

Before creating any artifact, research the technologies the agent will need to know:

```
/researching-technical-frameworks
```

### 2. Create each skill with the skill-creator

For each knowledge area of the domain, run:

```
/skill-creator
```

Skills are created at `.claude/skills/{skill-name}/SKILL.md` following the three-tier pattern.

### 3. Choose the correct agent type

| Type | When | Generates code? |
|------|--------|:---:|
| **Implementation** | Agent that will generate/modify code | ✅ |
| **Advisory** | Agent that produces designs, ADRs, recommendations | ❌ |
| **Orchestrator** | Agent that coordinates multiple domains | ✅ |

### 4. Expected project structure

Organize the generated artifacts under `.claude/`:

```
.claude/
├── agents/
│   └── {domain}.md                  ← Agent definition (P0-P5)
├── rules/
│   ├── {domain}-config.md           ← Project setup
│   ├── {domain}-standards.md        ← Code patterns
│   └── {domain}-skills.md           ← Routing table
├── skills/
│   └── {domain}/
│       └── SKILL.md                 ← Main skill + blueprints/
```

### 5. Validate the routing structure

```
/agent-router-pattern-validator
```

### 6. (Optional) Full audit

```
/audit-cc-architecture-consensus
```

## Agent Types in Detail

### Implementation Agent
- Follows full P0-P5
- Loads skills → extracts patterns → generates code → validates
- Needs `tools: ['read', 'editFiles', 'createFile', 'runInTerminal', 'search']`

### Advisory Agent
- Follows P0-P5 but P4 is "Deliver" (not "Implement")
- Produces: ADRs, diagrams, roadmaps, delegation plans
- **Delegates** implementation to other agents
- Needs `tools: ['read', 'search']` (no edit/create)

### Orchestrator Agent
- Coordinates multiple domains (e.g., Java + Terraform)
- Maintains cross-domain dependency order
- Needs all tools

---

## Tips

- **Start with advisory**: If you're unsure about the design, create an advisory agent first to define the architecture, then an implementation agent to execute.
- **Skill granularity**: Prefer focused skills (1 service/concept) vs mega-skills. Facilitates composition.
- **Routing table**: The `{domain}-skills.md` file in `.claude/rules/` is the "map" that tells the agent which skill to load based on request keywords.

## Common Pitfalls

| Pitfall | Solution |
|-----------|---------|
| Creating skills without prior research | Research first with `/researching-technical-frameworks` — avoids hallucinations |
| Agent without skills (hardcoded knowledge) | Always externalize knowledge in skills |
| Overly generic skill ("cloud-stuff") | One skill per specific service/concept |
| Not validating after creation | Run `/agent-router-pattern-validator` and `/project-analysis-validator .claude/` |

## Creating the Files Manually (without bootstrap)

Since `agent-bootstrap` was cancelled, the 4 agent definition files need to be
created manually. Use the available templates as a starting point.

### Files to create

| File | Purpose | Reference template |
|----------|-----------|----------------------|
| `.claude/agents/{domain}.md` | Agent persona (P0-P5) | `.claude/templates/agents/TEMPLATE.AGENT.md` |
| `.claude/rules/{domain}-config.md` | Project setup (paths:, versions) | `.claude/templates/rules/TEMPLATE.CONFIG.md` |
| `.claude/rules/{domain}-standards.md` | Code patterns and naming | `.claude/templates/rules/TEMPLATE.STANDARDS.md` |
| `.claude/rules/{domain}-skills.md` | Routing table: keywords → skills to load | `.claude/templates/rules/TEMPLATE.SKILLS.md` |

### Recommended creation order

```
1. Copy agent template:
   cp .claude/templates/agents/TEMPLATE.AGENT.md .claude/agents/{domain}.md

2. Copy rules templates:
   cp .claude/templates/rules/TEMPLATE.CONFIG.md    .claude/rules/{domain}-config.md
   cp .claude/templates/rules/TEMPLATE.STANDARDS.md .claude/rules/{domain}-standards.md
   cp .claude/templates/rules/TEMPLATE.SKILLS.md    .claude/rules/{domain}-skills.md

3. Edit each file:
   - agents/{domain}.md: name, persona, skills to load at P0
   - {domain}-config.md: paths: for the domain files (e.g., "**/*.tf")
   - {domain}-standards.md: domain code patterns
   - {domain}-skills.md: keyword → skill-name table

4. Create the skills (if they don't exist yet):
   /skill-creator StoryBeat/research_{Tech}_v{Version}.md
```

### Minimum frontmatter by type

**Agent** (`.claude/agents/{domain}.md`):
```yaml
---
name: {domain}
description: >-
  {Domain} agent. Implements P0-P5 workflow for {domain} tasks.
  Use when working with {domain} projects.
tools: ['Read', 'Edit', 'Write', 'Bash']
---
```

**Rule** (`.claude/rules/{domain}-skills.md`):
```yaml
---
description: Skill routing for {domain} domain
paths: "**/*.{ext}"
---
```
