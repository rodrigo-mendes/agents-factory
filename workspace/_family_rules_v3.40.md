## Policy decisions
1. **Quarkus 4**: never a row in Never Do (Version Context + the register's `Version-lifetime risk` already carry it). Wherever "no Camel Quarkus build on Quarkus 4 is known" is stated, tag it `(medium confidence, absence of evidence)`, including in blueprints, migration guides and evaluation scenarios, and list it once in the register's medium list. Only the Beta1 post facts (published 2026-10-01, GA planned end of November, Java 21 base) are High.
2. **Global TLS widening** (`quarkus.tls.protocols`): Ask First, never Never Do (inbound impact unverified). Unknown/OpenSSL-style names FAIL SSL context creation since 3.40.0 is High (migration guide); say "fail SSL context creation" everywhere, not "fail startup".
3. **Dead Letter Channel default (6 redeliveries / 1 s)**: UNVERIFIED everywhere (only a tool summary saw it).
4. **`@ApplicationScoped` severity** in never-do blueprints: low (boot-time cost only). Never "mandatory".
5. **Evidence rule for confidence** (replaces ad-hoc "single page"): a claim is High only if its evidence is a VERSIONED official page (camel-quarkus/3.40.x, components/4.22.x, quarkus.io/version/3.40, source at tag 3.40.0, Maven Central POM) read by the researcher; unversioned manual pages, "latest" Quarkus guides, main-branch examples and partly-read guides are at most medium. Being a single source does NOT by itself lower a versioned claim to medium. Apply it consistently inside each skill: SKILL.md, blueprints and register must carry the same tag for the same claim.
6. **Always Do**: ONE High claim per bullet, each with an inline URL; no caveats inside the bullet (move them to Ask First / Quick Reference). Never Do: High rows only and the ✅ alternative also High. Nothing medium or unverified in either tier (move it to Ask First or the blueprint with the tag).
7. **Tag notation**: plain parentheses, `(medium confidence)` and `(unverified)`; no bold. Rows without a page: `page not recorded` (never `none`, `none recorded`, or a relative path).
8. **Register shape** (`blueprints/unverified-and-risks.md`): sections `Version-lifetime risk`, unverified items (U1..), irresolvable items (I1..), medium-confidence items (M1..), `Tag to register mapping` table with columns `Tag text used in the skill | Where | Register id`, and `Source Bibliography`. Header counts equal the listed items. EVERY `(medium confidence)` / `(unverified)` tag used anywhere in the skill (SKILL.md and blueprints, including `(log output unverified)`-style tags and tags on code samples) must have a mapping row. The Camel Quarkus-specific LTS end date and "does the 3.40 TLS bridging affect the inbound platform-http server" are tagged `(unverified)` in text (that is their family-facts tag): list them in the register's UNVERIFIED section (U-ids) with the note "not resolvable from documentation"; do not file them under a separate irresolvable class that contradicts the text tag. Keep the irresolvable section only for other items the research could not resolve, and keep header counts consistent with whatever sections you keep.
9. **Version Context rows**: Java = "17 and 21" High with the q-3.40.0 URL (above); Maven/GraalVM only if the skill's research has a page for them, else `page not recorded` tagged `(unverified)`.
10. **junit**: Camel side rename/stub facts live in `developing-camel-quarkus-junit-v3-40`; Quarkus side rename (`quarkus-junit5` -> `quarkus-junit` in Quarkus 3.31, relocation POM at 3.40.1) lives in `developing-quarkus-junit-v3-40`. Other skills mention the Camel rename only briefly with the High family tag and point to the junit skills by name.
11. **Quick Reference Source column** holds the exact page URL (absolute https URL) or `page not recorded`; never a relative path.

## Additional decisions from the validation of the jaxb/arc/quarkus-junit/camel-quarkus-junit/quarkus-rest group
12. **Register IDs**: U1.. (unverified), I1.. (irresolvable, other than rule 8), M1.. (medium), L1.. (coverage limits: pages read only partly, e.g. "first 100k of 108,136 characters"). No `U-1`, `IRRESOLVABLE-1`, `MC1` variants.

16. **Quarkus CDI reference URL**: use the VERSIONED https://quarkus.io/version/3.40/guides/cdi-reference in Always/Never Do and blueprints; the unversioned URL stays only in the family-facts table.
17. **Partial reads**: the Quarkus 3.40 `getting-started-testing` guide was read to 100,000 of 108,136 characters (state it as a coverage limit, not "read in full").
18. **Test facts confidence** (same evidence rule, used consistently by quarkus-junit and camel-quarkus-junit): "an `@QuarkusIntegrationTest` can extend a `@QuarkusTest` class" rests on a main-branch example: medium; "integration tests run in the prod profile and ignore test application.properties" and "`@QuarkusTestResource` is global by default": medium (single unversioned/partial evidence in quarkus-junit's register M-2/M-4): tag them the same way in both skills.
19. **Severity labels** in headings ("(severity: medium)") collide with confidence tags: use "(severity: low|moderate|high)" wording only in never-do blueprints, never the word "medium" alone.
