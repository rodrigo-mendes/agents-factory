## Description (max 4000 chars for KDP)
Event-Driven Architecture is a deep, opinionated field guide for senior software architects and back-end engineers building cloud-native, distributed systems. It starts from first principles — what an event actually is, how temporal, spatial, and flow coupling really behave — and refuses to treat any pattern as a default. Every chapter is written to answer the only question that matters in production: should I use this here, and what will it cost me for the next five years?

The book moves methodically from foundations to the hardest problems in the field. You will model events as genuine domain facts instead of technical noise; choose between broker and mediator topologies, queues and distributed logs; build idempotent consumers under at-least-once delivery; and apply CQRS and Event Sourcing only where they earn their keep. Dedicated chapters confront the topics most books gloss over: coordinating cross-service consistency with sagas and compensating transactions, evolving event schemas without breaking consumers years later, and operating systems where the control flow is implicit — distributed tracing, correlation and causation IDs, consumer lag, dead-letter queues, and poison-message containment.

The final chapter consolidates everything through real fintech and e-commerce case studies, a catalog of recurring anti-patterns, staged migration paths into and out of Event Sourcing, and a decision framework built around a single principle: coupling is a budget. Concrete code in Java, Kotlin, Python, and SQL, plus Mermaid diagrams, expert annotations, and skeptical critiques accompany every concept. This is not a cheerleading tour of event-driven buzzwords — it is a practitioner's manual on when to adopt these patterns, when to refuse them, and how to live with the consequences either way.
