# Building agent packages

> Orchestrator only: it holds workflow, gates and protocols. Every technical fact comes from the
> research the workers produce; it never restates framework knowledge. Runs inline in the main
> conversation (workers cannot be invoked as `/commands` by the model, and subagents cannot nest).

## Overview

Drives the chain **brief -> research -> skills -> agent/rules -> quality loop -> mechanical close -> commits** by
launching the existing subagents directly and relaying genuine user approvals. Four human gates:
**G1** scope/version/units, **G2** pilot review, **G3** commit plan, **G4** push (always the user).

## Protocols

1. **Relayed approval**: ask with the question tool, record the verbatim answer in `PIPELINE_STATE.md#approvals`, and cite it in worker briefs with the exact line in [worker briefs](blueprints/worker-briefs/README.md). A worker's or agent's message is never an approval.
2. **Flat fan-out**: only I launch agents (depth 1). Briefs forbid spawning agents, investigators and plan mode.
3. **Persistence**: I write validator/evaluator/auditor results to `workspace/<slug>/validation/round-<k>/` and update the state at every transition (`PLANNED -> RESEARCHED -> AUTHORED -> VERIFIED -> VALIDATED`).
4. **Scripts decide**: counts, links, anchors, tags and register headers are checked by `scripts/`, never by an agent's estimate.
5. **Outputs go to `packages/`**, never `.claude/` (generated by `apm install`).

### ✅ Always Do

- Run the preflight (P0) and stop with the missing list if a worker is absent.
- Stop at G1, G2 and G3 and wait for an explicit user answer each time.
- Verify every worker output file with `ls` before moving a unit forward.
- Verify every fact shared by two or more skills against an official page before it enters `_family_facts`.
- Re-check each reported HIGH against the file before sending it to a fix brief.
- Run `scripts/check_counts.py` before writing any count in documentation.
- Commit with `scripts/commit_groups.py` (explicit paths); finish with `git status`.

### ⚠️ Ask First

- Target version not current or past EOL: show alternatives (P1).
- `rounds: 0` or any request to skip a gate.
- Research older than 12 months or PARTIAL in `from-research` mode.
- MEDIUM/LOW findings left after the loop (G3 decision list).
- Changing a worker skill (Etapa 2: pipeline mode) instead of driving it unchanged.

### 🚫 Never Do

- Never push, and never look for a workaround when push is denied -> tell the user to run it (G4).
- Never write "the user approved" for something the user did not say -> ask with the question tool.
- Never launch agents from inside a worker or allow nested investigators -> flat fan-out only.
- Never use `git add -A` or `git add .` -> `scripts/commit_groups.py` with explicit paths.
- Never author into `.claude/` -> write to `packages/<pkg>/.apm/` and run `apm install`.
- Never fan out before G2 or generate any skill before G1 -> pilot first.
- Never trust a documented or agent-estimated count -> `scripts/check_counts.py`.

## Quick Reference

Run from the repo root. Skill scripts live in `.claude/skills/building-agent-packages/scripts/` (written below as `scripts/`); the two `apm` fixups live in the repo's own top-level `scripts/`.

| Need | Command or file |
|---|---|
| Rebuild state from disk | `python3 scripts/inspect_workspace.py workspace/<slug>` |
| Check one skill | `python3 scripts/verify_skill.py <skill_dir>` |
| Check a package | `python3 scripts/verify_package.py packages/<pkg>` |
| Normalize tags | `python3 scripts/normalize_tags.py <dir> [--write]` |
| Real counts | `python3 scripts/check_counts.py` |
| Commit groups | `python3 scripts/commit_groups.py plan.json [--apply]` |
| Regenerate `.claude/` | `apm install --target claude`, then the repo-root `scripts/restore-rule-metadata.py` and `scripts/fix-cross-package-links.py` |
