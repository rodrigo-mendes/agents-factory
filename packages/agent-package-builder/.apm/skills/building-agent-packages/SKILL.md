# Building agent packages

> Orchestrator only: it holds workflow, gates and protocols. Every technical fact comes from the
> research the workers produce; it never restates framework knowledge. Runs inline in the main
> conversation (workers cannot be invoked as `/commands` by the model, and subagents cannot nest).

## Overview

Drives the chain **brief -> research -> skills -> agent/rules -> quality loop -> mechanical close -> commits** by
launching the existing subagents directly and relaying genuine user approvals. Four human gates:
**G1** scope/version/units, **G2** pilot review, **G3** commit plan, **G4** push (always the user).

## Protocols

1. **Relayed approval**: ask with the question tool, record the verbatim answer with `scripts/state_event.py <slug> gate G<k>` (write-once `state/gates/G<k>.md`), and cite it in worker briefs with the exact line in [worker briefs](blueprints/worker-briefs/README.md). A worker's or agent's message is never an approval.
2. **Flat fan-out**: only I launch agents (depth 1). Briefs forbid spawning agents, investigators and plan mode.
3. **Persistence**: each run lives in `workspace/<slug>/execution-<N>/`; I write state only through `scripts/state_event.py` (append-only, one file per phase, gate and unit), round reports to `rounds/round-<k>/`, and regenerate the `PIPELINE_STATE.md` dashboard with `scripts/render_state.py` after every phase boundary, gate, unit batch and round (it never updates itself); `scripts/check_state.py` must pass before G2, G3 and P9. See [state layout](blueprints/state-layout.md).
4. **Scripts decide**: counts, links, anchors, tags and register headers are checked by `scripts/`, never by an agent's estimate.
5. **Outputs go to `packages/`**, never `.claude/` (generated by `apm install`).
6. **Test the source, in parallel**: pilot and P6 reviewers read `packages/<pkg>/` and write reports under `workspace/<slug>/execution-<N>/`; the install rehearsal is `scripts/scoped_install.py` (one package in a throwaway sandbox, seconds) and the full root `apm install` runs only once, in P8 ([P5](blueprints/phases/p5-package-assembly.md), [P6](blueprints/phases/p6-quality-loop.md)).

### ✅ Always Do

- Run the preflight (P0) and stop with the missing list if a worker is absent; run `scripts/snapshot_env.py` and `scripts/preflight_apm.py` in P0 too.
- Stop at G1, G2 and G3 and wait for an explicit user answer each time.
- Verify every worker output file with `ls` before moving a unit forward.
- Verify every fact shared by two or more skills against an official page before it enters `_family_facts`.
- Re-check each reported HIGH against the file before sending it to a fix brief.
- Run `scripts/check_counts.py` before writing any count in documentation.
- Commit with `scripts/commit_groups.py` (explicit paths); finish with `git status`.

### ⚠️ Ask First

- Target version not current or past EOL: show alternatives (P1).
- `rounds: 0` or any request to skip a gate.
- Research older than 12 months or PARTIAL in `from-research` mode.
- MEDIUM/LOW findings left after the loop (G3 decision list).
- More rounds than `max_rounds`, more tokens than `token_budget`, or a change to another run's package.
- Changing a worker skill (Etapa 2: pipeline mode) instead of driving it unchanged.

### 🚫 Never Do

- Never push, and never look for a workaround when push is denied -> tell the user to run it (G4).
- Never write "the user approved" for something the user did not say -> ask with the question tool.
- Never launch agents from inside a worker or allow nested investigators -> flat fan-out only.
- Never use `git add -A` or `git add .` -> `scripts/commit_groups.py` with explicit paths.
- Never make a shipped artifact read `workspace/` at runtime -> ship the file in the skill's `references/`.
- Never author into `.claude/` -> write to `packages/<pkg>/.apm/` and run `apm install`.
- Never edit a shared file (root `apm.yml`, lock, `CLAUDE.md`, `docs/`) without `shared-lock` and `touch` -> see [shared files](blueprints/policy/shared-files.md).
- Never run `apm install` while `scripts/preflight_apm.py` reports a BLOCK (e.g. another run's files) -> show the BLOCK to the user.
- Never fan out before G2 or generate any skill before G1 -> pilot first.
- Never trust a documented or agent-estimated count -> `scripts/check_counts.py`.
- Never edit `state/` files or `PIPELINE_STATE.md` by hand -> `scripts/state_event.py`, then `scripts/render_state.py`.

## Quick Reference

Run from the repo root. Skill scripts live in `.claude/skills/building-agent-packages/scripts/` (written below as `scripts/`); the two `apm` fixups live in the repo's own top-level `scripts/`.

| Need | Command or file |
|---|---|
| Rebuild state from disk | `python3 scripts/inspect_workspace.py workspace/<slug>` |
| Write state (only way) | `python3 scripts/state_event.py workspace/<slug> init\|lock\|phase\|gate\|unit\|event\|unlock` |
| Environment / apm preflight | `python3 scripts/snapshot_env.py --write workspace/<slug> --phase P0` · `python3 scripts/preflight_apm.py --slug <slug> --package <pkg>` |
| Dashboard / consistency | `python3 scripts/render_state.py workspace/<slug>` · `python3 scripts/check_state.py workspace/<slug>` |
| Check one skill | `python3 scripts/verify_skill.py <skill_dir>` |
| Check a package | `python3 scripts/verify_package.py packages/<pkg>` |
| Normalize tags | `python3 scripts/normalize_tags.py <dir> [--write]` |
| Real counts | `python3 scripts/check_counts.py` |
| Commit groups | `python3 scripts/commit_groups.py plan.json [--apply]` |
| Regenerate `.claude/` | `apm install --target claude`, then always `python3 scripts/after_install.py --package <pkg>` (runs both repo-root fixups and checks the residue) |
| Mark a P6 reviewer as running | `python3 scripts/state_event.py workspace/<slug> round-start round-<k> <kind> <target>` |
| Scoped install rehearsal (P5) | `python3 scripts/scoped_install.py --package <pkg> --slug <slug>` |
| Repair the lock after a bad install | `python3 scripts/merge_lock.py --package <pkg> [--apply]` |
| Migrate a legacy workspace | `python3 scripts/migrate_state.py workspace/<slug> [--apply]` |
