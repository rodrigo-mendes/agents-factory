# Ask-first decisions, CFK 3.4.0

Back to [SKILL.md](../SKILL.md). Decisions below have options that depend on the user's environment, or rest on one page. Ask before acting. S-ids are in the [bibliography](./unverified-and-risks.md#source-bibliography).

## Decisions

### Authorization model (C1)
| Option | Optimizes | Sacrifices |
|---|---|---|
| RBAC: `authorization.type: rbac`, MDS with LDAP, OAuth, file or mTLS provider, token key pair, KafkaRestClass (S18) | Central role bindings, `ConfluentRolebinding` CRs, audit logs | Needs an identity provider and MDS. RBAC is an Enterprise feature (S4) (medium confidence, M32). Cannot be turned off once set up (S24) |
| Simple ACLs: `authorization.type: simple` (S19) | Per-resource ACLs, fewer parts | No role model. License status of ACLs after trial expiry is not stated (unverified) |
| None: authorization is optional (S17) | Simplest | No access control; disposable dev clusters only |

Ask: "Do you hold a Confluent Enterprise subscription, and which identity provider (LDAP, OAuth, mTLS) do you run?"
Note: the simple-ACL example uses `kafka.security.authorizer.AclAuthorizer`, which the same page calls the ZooKeeper-only class (CP 7.9 and earlier). For KRaft the alternate class is `StandardAuthorizer`, and the default class already handles RBAC and ACLs in both modes (S19) (medium confidence).

### TLS certificates (C2)
Options: `tls.autoGeneratedCerts: true` with a CA you supply, or user-provided certificates in a secret (`fullchain.pem`/`privkey.pem`/`cacerts.pem`, `tls.crt`/`tls.key`/`ca.crt`, or JKS) or a Vault path (JKS only) (S15) (medium confidence).
- Auto-generated: CFK issues and renews (365 days by default; Helm `certDurationInDays` default 60), fits traffic inside Kubernetes (S15).
- User-provided: your PKI and external client trust; you manage SANs and rotation (S15).
Ask: "Do clients connect from outside the Kubernetes cluster?" The mechanism cannot change after deploy (S24).

### External access type (C3)
Options: `loadBalancer`, `nodePort`, `route`, `staticForPortBasedRouting`, `staticForHostBasedRouting` (S9). The mechanism cannot change after deploy, and a domain or port change may need a Kafka restart (S24). Per-option tradeoffs are not on the pages read (unverified). Ask: "Which ingress does the platform offer?"

### Install method and CRD management (C4)
Helm repo (simplest, needs access to packages.confluent.io), download bundle (air-gapped), OpenShift OperatorHub (namespaced only, no license key parameter, CSV edits lost on upgrade) (S5). `manageCRDs` defaults to `true` (`false` on OpenShift), or apply CRDs yourself with `kubectl apply --server-side=true` (S6) (medium confidence). Ask: "Is the cluster air-gapped or OpenShift, and may the operator hold cluster-wide CRD permissions?"

### License delivery (C5)
Global (`--set licenseKey=<key>` plus `spec.license.globalLicense: true`), per-component `spec.license.secretRef` with a `license.txt` key, or `spec.license.directoryPathInContainer` (Vault, takes precedence if both are set). Component licenses override the CFK license. Both API methods need a rolling restart (S3) (medium confidence). Ask: "Does a single subscription cover all components?"

### Self-Balancing trigger (C6)
Default `EMPTY_BROKER`, or `ANY_UNEVEN_LOAD` set in both Kafka and KRaftController `configOverrides`. Limit movement with `confluent.balancer.*.max.bytes.per.second` (S20) (medium confidence). Ask: "Can the cluster tolerate background partition movement?"

### Connect plugin delivery (C7)
`build.type: onDemand` (Confluent Hub or URL with sha512 `checksum`; 4 GB node volume by default) or an image extended from `cp-server-connect:<CP release>` (S25) (medium confidence). Ask: "May pods download from the internet at startup?"

### Heap sizing policy (C8)
The 3.4 default cap, a pinned `-Xms`/`-Xmx`, or `-XX:MaxRAMPercentage` after removing defaults with `---Xmx` and `---Xms`. Without a pod memory limit a percentage heap is computed from node memory (S21) (medium confidence).

### Monitoring stack (C9)
See [observability](./observability.md) (medium confidence).

### Upgrade order and CFK versus Strimzi
- Upgrade CFK first, then CP (S7) (medium confidence). CP order on KRaft: controllers, brokers, metadata version, other components, Control Center (S8) (medium confidence).
- Strimzi 1.3.0 supports Kafka 4.2.0, 4.2.1, 4.2.2, 4.3.0, 4.3.1 on Kubernetes 1.32-1.37 (tested); Kafka 4.4.0 is not listed (https://strimzi.io/downloads/, read 2026-11-04). Strimzi content lives in `operating-kafka-strimzi-v1-3`.

## Single-source cautions (not Never Do candidates)

Each rests on one page, so each is a question or a warning here, not a rule.

| Caution | Source | Tag |
|---|---|---|
| Do not set both `zookeeper` and `kRaftController` in `Kafka.spec.dependencies`; Kafka fails to start | S9 | (medium confidence) |
| Do not use `kafka-features --release-version` on CFK-managed clusters: it raises `kraft.version` from 0 to 1, which CFK does not support. Use `--metadata` only | S8 | (medium confidence) |
| Raise the metadata version after a cluster health check, with `kafka-features ... upgrade --metadata <x.y>` | S8 | (medium confidence) |
| Use `reclaimPolicy: Retain` (page says required for production) and `allowVolumeExpansion: true`; do not use the default StorageClass in production; with `persistentVolumeReclaimPolicy: Delete`, `kubectl delete kafka` deletes the data | S12 | (medium confidence) |
| Give all brokers the same disk size (mismatch causes a `DiskUsageDistributionGoal` violation); do not shrink multi-AZ or multi-rack clusters; do not remove a broker from the middle of the ID range; do not edit `platform.confluent.io/enable-shrink` or `cluster-scale-metadata`; do not resize ZooKeeper with `kubectl scale` | S20 | (medium confidence) |
| Enable `oneReplicaPerNode: true` (disabled by default; changing it rolls the cluster) | S27 | (medium confidence) |
| Spread pods across zones with `podTemplate.topologySpreadConstraints`; CFK does not guarantee an even spread | S26 | (medium confidence) |
| Enable TLS at first deploy; it cannot be enabled on a TLS-disabled cluster later | S24 | (medium confidence) |
| Use a unique TLS secret per component; do not use the example JKS script in production | S15 | (medium confidence) |
| Run `helm upgrade ... --dry-run` with your values file before the real upgrade | S6 | (medium confidence) |
| With `rbac: false`, add the `customresourcedefinitions` ClusterRole rule (get, list, watch, create, update, patch) before upgrading to 3.4 | S7 | (medium confidence) |
| Do not delete the `confluent-operator-licensing` and `internal-confluent-operator-licensing` secrets; do not restart Kafka with the generic component roll after a license change (the page warns of possible data loss), use the Kafka restart procedure | S3 | (medium confidence) |
