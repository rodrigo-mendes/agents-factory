## Settings fixed after deployment (S24)

Decide these before the first deploy. CFK cannot change them in place:
- RBAC on (cannot be turned off).
- Certificate mechanism (auto-generated versus user-provided).
- Enabling TLS on a TLS-disabled cluster.
- Listener authentication mechanism.
- Metrics TLS and authentication.
- External access mechanism.
- Storage class.
- Secrets mechanism (Kubernetes secrets versus directory path).

Logs are lost on pod restart, so plan log retention early (S24).

## Authentication (S16)

- CFK configures Kafka, KRaft and MDS without authentication unless you set it.
- Server-side SASL/PLAIN secret keys: `plain-users.json`, `plain-interbroker.txt`. Client side: `plain.txt`. Pass-through: `plain-jaas.conf`. Files must use LF line endings.
- Client components set the same block under `dependencies.kRaftController.controllerListener.authentication`.
- Credential wiring through `jaasConfig.secretRef` or `jaasConfigPassThrough` (secretRef or `directoryPathInContainer`).

## Authorization

- Simple ACLs: `authorization.type: simple` in the KRaftController and Kafka CRs (S19).
- RBAC: KRaftController CR needs `authorization.type: rbac`, `superUsers`, `dependencies.mdsKafkaCluster` (S18). MDS needs an LDAP, OAuth, file or mTLS provider, a token key pair and a KafkaRestClass (S18). Role bindings are `ConfluentRolebinding` CRs.
- RBAC is an Enterprise feature (S4) (medium confidence, M32). See [licensing](./licensing.md).
- The `AclAuthorizer` class in the simple-ACL example is the ZooKeeper-only class; for KRaft use the default class or `StandardAuthorizer` (S19) (medium confidence).
- ACL behavior after license expiry is not documented (unverified, I2).
- If you manage CFK RBAC yourself (`rbac: false`), add the `customresourcedefinitions` ClusterRole rule before upgrading to 3.4 (S7) (medium confidence).

```bash
kubectl get confluentrolebinding -n <namespace>     # representative (S18)
```

## TLS (S15)

- `tls.autoGeneratedCerts: true` with a CA you supply (CR annotations, Helm `managedCerts`, or legacy `ca-pair-sslcerts`), or user-provided certificates in a secret or Vault path. Option tradeoffs: [ask-first C2](./ask-first-decisions.md#tls-certificates-c2) (medium confidence).
- Use a unique TLS secret per component; do not use the example JKS script in production (medium confidence).
- Enable TLS at first deploy; it cannot be enabled later (S24) (medium confidence).
- CP 8.0 enables the SNI host check by default; CFK 3.4.0 adds `spec.internalClientConfig.endpointIdentificationAlgorithm` (default `https`); dynamic certificate rotation without a roll applies only to Kafka and Kafka REST PEM `secretRef` listener certificates, after enabling `platform.confluent.io/enable-dynamic-configs` (S15) (medium confidence).
- Prometheus has no TLS or mTLS in CFK (S23).

## Gateway CRs

Confluent Gateway CRs written with 3.3 security settings are not compatible with 3.4; route settings move under `security.cluster.<streaming-domain>` (S7) (medium confidence).
