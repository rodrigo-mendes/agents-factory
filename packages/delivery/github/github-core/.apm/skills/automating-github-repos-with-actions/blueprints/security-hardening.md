# Security hardening (GitHub.com Actions, as of 2026-10-29)

Back to [SKILL.md](../SKILL.md). Sources fetched 2026-10-29: https://docs.github.com/en/actions/reference/security/secure-use unless stated.

## Checklist

- [ ] `permissions:` explicit; workflow default read-only or `{}`
- [ ] every action SHA-pinned, including `actions/*`
- [ ] no `${{ github.event.* }}` text in `run:`
- [ ] `author_association` check and an exact bot-login guard on comment and label triggers
- [ ] App token minted per job and narrowed (`repositories`, `permission-*`)
- [ ] no `pull_request_target` with PR code; no unreviewed `allow-unsafe-pr-checkout: true`
- [ ] classic PAT only for user-owned projects, with the risk warning
- [ ] Dependabot version updates enabled for the `github-actions` ecosystem

## Script injection

```yaml
# ❌ run: echo "${{ github.event.issue.title }}"
# ✅
env:
  TITLE: ${{ github.event.issue.title }}
run: printf '%s\n' "$TITLE"
```

Sources: secure-use ; https://docs.github.com/en/actions/concepts/security/script-injections

## Least privilege

- Default read-only: "set the default permission for the `GITHUB_TOKEN` to read access only for repository contents ... The permissions can then be increased, as required, for individual jobs".
- Naming any permission sets every unnamed one to `none`; `permissions: {}` disables all. Source also https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax
- Anyone with write access to the repository can read all of its secrets.

## Pinning

- Pin to a full-length commit SHA; verify it "is from the action's repository and not a repository fork".
- The repository setting "Require actions to be pinned to a full-length commit SHA" covers GitHub-authored actions. Source: https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/enabling-features-for-your-repository/managing-github-actions-settings-for-a-repository
- Floating major tags pick up behaviour changes silently: checkout v7 added its fork-PR refusal on 2026-06-18 and the change was backported to the floating v3 to v6 tags on 2026-07-20; SHA, minor and patch pins were unaffected. Source: https://github.com/actions/checkout/releases ; https://github.blog/changelog/2026-06-18-safer-pull_request_target-defaults-for-github-actions-checkout/
- Resolve a tag before pinning: `git ls-remote https://github.com/actions/create-github-app-token refs/tags/v3.3.0` expects `64ab729a6294000f5aa4a4bc0b73d1f32bc45510`.

## Lockfile alternative

Workflow dependency lockfiles (generated by the `gh actions-lock` extension) entered public preview on 2026-10-14, and the secure-use page says they supersede SHA pinning for repositories that adopt them (medium confidence: preview feature). Default to SHA pinning; ask before adopting the lockfile. Source: https://github.blog/changelog/2026-10-14-github-actions-workflow-lockfiles-in-public-preview/

## pull_request_target and forks

- `pull_request_target` runs in the base repository context with secrets; "Avoid using this event if you need to build or run code from the pull request". Vulnerable workflows can be exploited "to take over a repository". Source: https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows
- Checkout v7 refuses fork PR code under `pull_request_target`, and under `workflow_run` when the triggering event is a pull request, unless `allow-unsafe-pr-checkout: true` (default `false`). Source: https://github.com/actions/checkout/releases/tag/v7.0.0
- Fork PRs under `pull_request` get a read-only `GITHUB_TOKEN` and no other secrets; treat Dependabot PRs as forks.

## Secrets

- "Sensitive data should never be stored as plaintext in workflow files."
- "Never use structured data as a secret": redaction is an exact match. Keep the App client id in `vars` and the private key in `secrets`.
- Rotate secrets periodically and avoid printing them.

## Verification commands

```bash
# representative; run from the repository root
grep -nE 'run:.*\$\{\{ *github\.event\.' workflows/*.yml                  # expected: no matches
grep -nE 'uses: [^ ]+@(v[0-9]+[^ ]*|main|master)\s*$' workflows/*.yml     # expected: no matches
grep -c '^permissions:' workflows/*.yml                                    # expected: one hit per file
```

Run the greps from the directory that holds the workflow files. They are heuristics; the community linter in [runners and scripts](./runners-and-scripts.md#offline-linting) is stricter.
